# GnT — paired Genome-and-Transcriptome single-cell sequencing

**GnT = paired single-cell DNA + RNA sequencing from the *same* physical cell**
(a G&T-seq-style plate-based protocol), generated by the Van Loo lab at the
Crick (data produced ~2021, Yan H / hyan) and deposited at EGA. It is a
**third, independent single-cell technology** for this patient, alongside the
**10X** and **DLP+** scDNA technologies already documented in
[`scDNA/`](../scDNA/) and the snRNA-seq documented in [`scRNA/`](../scRNA/).
Unlike those two, GnT gives a **direct, cell-level DNA↔RNA pairing** — no
cross-technology clone matching is needed, because the DNA and RNA reads for
a "GnT cell" come from the same lysed cell split into two aliquots.

Everything below documents what exists in the Zenodo release and in the
raw/big data store, as a starting point for building a pipeline here. The
first analysis stage now exists:

- [`1_genedosage/`](1_genedosage/) — does DNA copy number predict RNA
  expression? Reproduces the manuscript's gene-dosage panel (published as
  Figure 2E).

## Experimental design

Six regions (`P`, `R1`–`R5`), same patient as the rest of this repo. Per
region, single cells were sorted into a 96-well plate and each cell's lysate
was split so that **one well of a companion plate got the DNA fraction and
the paired well got the RNA fraction** — i.e. ~96 cells attempted per region
× 6 regions = **576 cells attempted**, each yielding one DNA fastq pair and
one RNA fastq pair. DNA and RNA libraries for the same cell were sequenced
back-to-back and deposited at EGA with **adjacent accession numbers**
(RNA accession = DNA accession − 1, e.g. `EGAF00003441284`=RNA,
`EGAF00003441285`=DNA, both region R1). That adjacency — not a barcode in
the conventional 10X/DLP+ sense — **is** the DNA↔RNA identity mapping for
GnT, and it is confirmed (not just assumed) by genotype-concordance checks
(see below).

**Reference genome note:** GnT DNA was aligned to **GRCh37**
(`human_g1k_v37.fasta` / `Homo_sapiens.GRCh37.dna.all.fa`), not hg38. This
differs from every other DNA stage in this repo (`scDNA/` uses `hg38-gatk`
and `hg38-ngs`). Any coordinate-based join against `scDNA/2_clustering/`
CN profiles needs a liftover. GnT RNA was aligned to hg38 (STAR).

## Answering the three questions directly

- **Cell-count matrix?** Yes, but split by modality: `GnT_scRNA_MPNST_C.rds`
  (Zenodo) is a standard Seurat count matrix, 300 RNA cells. A DNA-side
  count/CN matrix for more cells (216, pre-RNA-matching QC) exists only in
  the raw data store (`MPNST_GnT_totCN_mtx.rds`). There is **no single
  published wide cell×gene matrix combining both modalities** — the combined
  data is the long-format `MPNST_GnT_cell_seg_exp.rds` (130 cells).
- **ASCAT.sc profile?** Yes — per-cell ASCAT.sc profiles exist for all 576
  attempted GnT-DNA cells in the raw data store
  (`Haixi/GnT/results/ASCAT.sc/`, consolidated in
  `results/ASCAT.sc_10X_DLP/GnT_allProfs.rds`), harmonized onto the same bins
  as the 10X/DLP+ ASCAT.sc runs. None of this raw/intermediate ASCAT.sc
  output was included in the Zenodo release or this repo.
- **RNA↔DNA mapping file?** Yes, at two levels of confidence: (1) the
  cheap version is EGAF-accession adjacency, tabulated per fastq file in
  `Haixi/metadata/GnT_fastq.csv`; (2) the verified version is the
  genotype-concordance check in `Haixi/GnT/code/GnT_genotype.R` /
  `results/Genotype_SNPs/`, `results/Genotype_de_novo_SNVs/`, which confirms
  a given DNA/RNA pair truly shares one cell of origin. Neither is
  reproduced in the Zenodo release; only the *result* of applying that
  mapping (the 130-cell joined table) is.
